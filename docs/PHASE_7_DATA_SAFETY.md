# Phase 7 data-loss review

The unchanged Phase 5/6 data-safety implementation was reviewed from merged main `5306cce4554b4d5ca1132905b7f0ce59dfb73b17`. Phase 7 adds one browser acceptance test for a missing local cache; it does not change the database schema, synchronization protocol, retention behavior or recovery rules. This review distinguishes automated fault injection from actual OS crashes and physical-device resets. Package-specific observations belong in [the Phase 7 release report](PHASE_7_RELEASE.md).

**SAFE** means the tested operation retains a complete committed state or rolls back incomplete work; it does not promise that unsaved input survives every OS/storage failure. **RECOVERABLE** means preserved data or cloud history can be restored, sometimes requiring an explicit version choice or backup import. **EXPECTED LOCAL-ONLY LOSS** means removing local storage can destroy data that was never uploaded or downloaded as a backup. A demonstrated unintended loss would be classified **BUG**; none was found in this audit.

## Additional acceptance test

The case **a missing local account cache pulls exact cloud history from zero without duplicate uploads or a premature Synced status** in `tests/stress-e2e/stress.spec.ts` uses actual browser IndexedDB and the ordinary client worker. Auth responses are mocked through the official Supabase SDK, while study RPCs execute the unchanged Phase 3 SQL in isolated PGlite. This is distinct from real hosted Auth/PostgREST, a Windows WebView2 package, or physical-device validation.

Its initial cloud-backed workspace includes one subject, one completed session spanning two original study days, and customized shared settings. It closes the application page before deleting only the known disposable account database from a same-origin inert test page. Browser Auth storage remains present. On reopen, the first SQL pull is held: the request starts at cursor `0`, study tables and local cursor remain empty, no successful-sync metadata exists, and the visible workspace status says **Syncing…**, with no **Synced** status. Device-local onboarding is marked complete using the existing test-fixture technique so that this ordinary status can be inspected; this does not queue a cloud write.

After releasing the pull, the recovered workspace contains exact study history, allocations, shared values and revisions, and reports **Synced**. It has no pending operations or conflicts. The number of apply RPCs and cloud subject/session/allocation rows is unchanged. The focused case passed locally (1/1, 9.9 seconds). The expanded full stress suite passed **17/17** locally in **2.2 minutes**, including this case in 7.3 seconds, on the stable Phase 7 source.

## Validation boundaries

The merged-main local baseline passed **16/16 stress**, **3/3 recovery**, **3/3 mobile/hardening**, and **5/5 standard PWA** tests. One optional OS-level PWA installation case was explicitly skipped. Baseline logs and newly generated observations were saved under ignored `work/phase7/baseline-hardening`; pre-existing tracked Phase 6 screenshots and mobile measurements were restored byte-for-byte.

After candidate source edits stopped, the complete recovery suite passed **3/3** again in **25.0 seconds** and the production-build PWA suite passed **5/5 standard cases** in **35.7 seconds**, with the same one explicitly optional OS-installation skip. Final logs and recovery screenshots were recorded under ignored `work/phase7/final-hardening`; the two original tracked recovery screenshots were restored with matching SHA-256 hashes.

A preliminary expanded stress run overlapped source edits and passed eight cases before nine setup/navigation failures caused by the development server's live module replacement. Its log and error contexts were retained separately. After source edits stopped, the development server was restarted and all seventeen cases passed without relaxing assertions or changing production behavior.

OS power loss, disk failure, literal browser-process termination during import and complete browser site-data clearing were not executed by this automated review. Test-environment cache deletion is restricted to newly created disposable data. The audit never deletes personal history, personal account caches or hosted cloud data.

No demonstrated data-loss bug was found by this review. Physical storage destruction and uncommitted local-only data require transparent documentation rather than a new backup/synchronization architecture in Phase 7.
